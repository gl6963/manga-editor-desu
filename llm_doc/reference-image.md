# 設定資料（参照画像 / Nano Banana）

コマの生成時に参照画像を一緒に送る仕組み。**Google Nano Banana専用**。
ComfyUI・SD WebUI・Fal.aiは画像を1枚（Inpaintのみマスク込みで2枚）しか送れないため対応しない。
（この画面から**資料そのものを作る**のは全プロバイダー対応。→「この場で作る」）

## 送られるかどうかを画面に出す

**対応の有無は`AIProvider.supportsReferenceSheets()`が持つ。** 既定は`false`で、
`GoogleImageProvider`だけが`true`を返す。対応が増えたときに直すのはここ1か所。
対応サービスの名前も`providerRegistry.getAll()`から数え上げる（文言に書き並べると、
対応が増えたときにそこだけ古いまま残る）。

`deliveryState()`（reference-sheet-window.js）が、そのコマの生成で**実際に呼ばれるロール1つ**を見る。
絵が入っているコマはI2I、空のコマはT2I（枚数と説明文の番号も同じ`hasSourceImage()`を使っている）。

| 状態 | 画面 |
|------|------|
| ロールが未割り当て | `refNotSentNoRole` |
| 対応していないサービス | `refNotSentUnsupported` |
| 送られるが、モデルが人物の一貫性に非対応 | `refNoticeNoCharacterRef` |
| 送られるが、モデルが表に無い | `refNoticeUnlistedModel` |

- **枚数だけ出してはいけない。** 「送る画像 3 / 14」「トークン ~1,548」と数字が出ていると
  送られていると読める。送られない設定のときは`.rs-bar.is-undelivered`で枚数とトークンを
  取り消し線にし、理由を`#rsModelNotice`に出す
- **注意書きは枚数のすぐ下に置く。** 下端に置くと、数字を見ている目には入らない
- 送られないのなら、モデルの対応まで言っても行き先が無い（`deliveryMessages()`は先に返す）
- 資料が1枚も付いていないコマでは出さない（用の無い注意書きは本体を狭くする）

警告文の色は`--color-accent`（#810000）ではなく`--btn-danger-color`。
`--color-accent`は塗りと枠の色で、暗い背景の上の文字としては読めない。

## 画面の呼び名とコードの名前

UIは「リファレンスシート」から**「設定資料」**へ言い換えた（カタカナで何をするものか読めなかったため）。
**コード側の名前は変えていない。** ファイル名・関数名・保存キーは`sheet` / `base`のまま。

| 画面 | コード | 備考 |
|------|--------|------|
| 設定資料 | referenceSheet / rs- | ウインドウ・ボタン・タイトル |
| この作品 | project | プロジェクトファイルに入る側 |
| 共通（共通の資料） | base | IndexedDBに入る側。作品をまたぐ |
| 送る画像 | count | コマへ送る枚数。元画像も1枚に数える |

8言語ぶん揃えてある。ja/ko/zhは現場の言葉（設定資料 / 설정 자료 / 设定资料）、
en/fr/es/ru/deは既存の「reference sheet」系のまま、`base`だけ「共通の書庫」の言い方へ寄せた。

## 保存の2層構造

| | 置き場所 | 範囲 | 正か |
|---|---------|------|------|
| **この作品の資料** | プロジェクトファイルの`reference_sheets.json` | そのプロジェクト | **正** |
| **共通の資料** | IndexedDB `MangaEditor_Reference/baseReferenceSheets` | 全プロジェクト共通 | 素材置き場 |

**IndexedDBだけに置いてはいけない。** 別PCやブラウザデータを消した後にプロジェクトを開くと、
コマ側に割り当てのidだけが残って実体が無くなる。フォントが同じ問題を`fonts.json`で解いているので、
同じ形にしてある（`project-font.js`）。

- 保存時は`buildProjectReferenceData()`が**そのページのコマが参照しているシートだけ**を集める。
  全シートを毎ページ入れるとプロジェクトファイルが膨らむため
- 読み込み時は`setProjectReferenceData()`が差し替える。**プロジェクトファイルの内容が正**
- **ベースのシートをコマに付けるとプロジェクトへ複製される**（`copyBaseToProject()`）。
  idで参照し続けると、ベースのキャラ表を直したときに過去の巻の絵まで変わってしまう。
  **複製したことを画面に出す**（`refCopiedToProject`）。黙って複製すると、
  共通側を直しても絵が変わらないのが不具合に見える。
  複製の入口は3つ（カードのボタン・サムネイル・枠へのドロップ）あるので、
  ウインドウ側の`resolveTargetId()`1か所に集める。
  **上限の判定は複製より手前で行う**（複製してから止めると、どのコマにも付いていない複製だけが残る）
- ベースはブラウザ側にしか無いのでJSONで書き出し・読み込みできる
  （`exportBase()` / `importBase()`。フォーマットキーは`manga-editor-desu.reference-sheets`）

### 同梱物を落とす経路に注意

ページのblobを作り直す処理が2か所ある。**どちらも`reference_sheets.json`と`fonts.json`を
引き継がないと実体が消える。**

- `generateProjectFileBufferList()`（project-compression.js）— 通常の保存
- `processImageOnOffscreenCanvas()`（generation-task-manager.js）— ページを離れた後に
  生成結果を元のページへ戻す経路。**元のblobから読み直して渡す**

zip読み込み側は状態ファイルを`state_*.json`に限定してある。除外リスト方式に戻すと、
メタファイルを足すたびに履歴状態として読み込まれる。

## なぜ説明文をプロンプトに付けるのか

**APIには画像の役割を示すフィールドが無い。** `input`配列に`{type:'image'}`を並べるだけで、
どれがキャラでどれが背景かを示す手段が無い。公式のプロンプト例はすべて
「the first image」「the second image」と**順番でテキストから指し示す**方式になっている。

このアプリのプロンプトはDanbooruタグの羅列なので、画像を並べただけではモデルは各画像が
何なのか分からない。そこでシート項目に説明文を持たせ、**送る順と同じ番号**を振った説明を
プロンプトの先頭に付ける。

```
Image 1: base image to edit
Image 2: previous panel of the same page, for visual continuity - コマ1
Image 3: character reference - ミナ (黒髪ロング、赤い目)

masterpiece, best quality, 1girl, simple background, , classroom, evening light
```

- 説明を付けるかどうかは`referenceDescribeInPrompt`で切り替えられる。効きが未検証のため
  試せる形にしてある
- **黙って足さない。** 実際に送る文面をウインドウ下部にそのまま出す
- `_composePrompt()`（google-image-provider.js）が組み立てる。**順番を変えるなら
  `ReferenceCollector.collectForLayer()`の並びも同時に変える。** 番号がずれると
  「Image 2の服を着せて」が別の画像を指す

## 資料どうしの関係（枠）

人物が2人以上出るコマでは、**どの小道具が誰のものかを示す手段が他に無い。**
説明文は1画像1行の羅列で、本文はDanbooruタグの羅列（`2girls, holding sword`）なので、
どちらの手に何があるかをタグ側でも書けない。

**同じ枠に入れた資料どうしが関係する。** 枠の先頭が基準で、残りはそれに掛かる。

```
referenceGroups: [ { ids:["<Aさんのid>","<刀のid>"], prompt:"右手に刀を持つ" },
                   { ids:["<背景のid>"], prompt:"" } ]
```

- **コマ枠に持つ。** 同じ刀のシートでも「1コマ目はAさんが持つ / 2コマ目はBさんが持つ /
  3コマ目は誰も持たない」をコマごとに切り替えられる。
  シートの`note`に書くと**そのシートを使う全コマに同じ文が乗る**ため、ここには置けない
- **番号ではなくidで結ぶ。** `Image N`は`buildPreamble()`が組み立てのたびに数え直す。
  自由記述に「Image 2の人物が」と書かせると、並べ替えたときに番号がずれて別の画像を指す
- **送る順も枠の並びが正。** 枠をまたいで前から数えたものが`Image N`になり、
  `referenceIds`は枠から作り直す。順番と組を別々に持つと、片方だけ直したときに食い違う。
  そのため**書き込みは`setGroups()`の1か所**に集める（付ける・外す・移す・欠落の削除も全部そこを通る）
- 付いていないidが枠に残らないよう、読み出し（`getGroups()`）で毎回突き合わせる。
  実体の無い参照と違い、関係は絵に出ないので残っていても気づけず、
  次に同じシートを付け直したときに蘇る
- `referenceGroups`を持たない古い保存は`referenceLinks`から読み替える（`groupsFromLinks()`）。
  関係先が同じものを1つの枠にまとめ、メモは枠のプロンプトへ移す
- **`referenceDescribeInPrompt`を切ると関係は1文字も送られない。**
  設定した本人には見えない差なので、関係があるときだけウインドウに出す

### 画面での見え方

関係は絵にも枚数にも出ない。**設定したこと自体が読めないと、付けたつもりで消えていても気づけない。**

**関係は枠で見せる。** 同じ枠に入っている＝関係がある。文字とプルダウンで説明すると、
資料の枚数だけ行が並んで壁になり、矢印の向きがどちらの所属を指すのかも読めない。

| 場所 | 出すもの | なぜ |
|------|---------|------|
| 送る順と関係 | 枠にサムネイルを並べる。番号は枠をまたいだ通し番号 | **1か所にまとめる。** 順番と関係を別のセクションに分けると、同じサムネイルが上下2か所に並び、どちらを見て直せばいいのか読めない |
| キャンバスのチップ | サムネイルを**全部**、**枠ごと囲んで**（コマの幅で折り返す）。文字はツールチップ | 鎖のアイコン1つでは「関係が付いている」ことしか分からず、何と何が組なのかは結局コマを選び直して確かめることになる |

- **1枚だけの枠は囲みを消す**（関係を持たないため）。全部囲むと、どれが組なのか読めない
- **同じ資料を複数の枠に入れられる。** 「Aさんとラーメン」「Bさんとラーメン」を別々に言えないと、
  人物ごとの持ち物を伝える手が無い。**送る画像は1枚のまま**（送る順は重複を持たない）で、
  説明文が`Image 2はImage 1と一緒` `Image 2はImage 3と一緒`の2行になる。
  同じ番号のスロットが並ぶことになるので、破線とツールチップで理由を出す（`.rs-slot.is-shared`）
- 同じ枠の中だけは重複させない（同じ組に同じ絵を2回入れても意味が増えない）
- **枠と枠の間隔は、枠の中の間隔より広く取る。** 同じ間隔だとどこで組が切れているのか読めない
- **枠の先頭が基準**で、残りはそれに掛かる。左端という位置だけでは枠が2つ並んだとき
  どちらの左端か読み違えるため、基準にはしるしを出す（`.rs-slot-anchor`）
- 落とした先が意味を決める
  - サムネイルの**左半分** … その手前へ（左端へ落とせば基準になる）
  - サムネイルの**右半分** … その次へ。**左だけしか受けないと、一番右へ足すときに
    落とせる場所が枠の細い余白しか無くなる**（`isAfterHalf()`）
  - 枠の余白 … その枠の末尾へ
  - どの枠でもない余白 / 「新しい枠」 … 1枚だけの枠になる。
    **余白へ落とすときも受け口を光らせる**（「新しい枠」に印を付ける）。
    光らないと、落ちたのか素通りしたのか分からない
- **掴んだものによって意味が変わる**（`dragPayload()` / `dropPayload()`）
  - スロット … その枠から抜いて**移す**（抜くのは掴んだ枠だけ。全部から抜くと
    同じ資料を使っている隣の枠まで壊れる）
  - 一覧のカード … その枠に**足す**。他の枠からは外さない
  - 掴んだものごとに受け口を書き分けると、受け口を1つ足すたびに全部へ書き足すことになる
- スロットの`×`は**押した枠から抜くだけ**。どの枠にも無くなればコマから外れる
- **名前はスロットの中で直せる。** 取り込んだ直後のファイル名がそのまま送る文面に載るため、
  直すのに一覧まで目を移すことにならないようにする。
  入力欄の`mousedown`でスロットの`draggable`を切り、`blur`で戻す
  （切らないと文字を選ぼうとしただけでドラッグが始まる）。
  書き換えたら一覧側の入力欄へ**作り直さずに当て直す**（作り直すとフォーカスが飛ぶ）
- **未入力の案内文（placeholder）は薄くする。** 本文と同じ色だと、名前が既に入っているように見える。
  入力欄を足すたびに書き忘れないよう、`.rs-window input::placeholder`の1か所で当てる
- **空の枠は持てない**（中身が0枚になった枠は畳まれる）。そのため「枠を作るボタン」ではなく
  「落とすと新しい枠になる受け口」を出す。付けたばかりの資料も1枚だけの枠に入る
- 枠のプロンプト（`右手に刀を持つ`）は**関係のある枠だけに出す**。1枚だけの枠にも出すと、
  関係を付けていない資料の数だけ入力欄が並んで壁になる。
  **枠が1枚に減ったら文面は捨てる**（`setGroups()`）。持ったままにすると入力欄から消えたまま残り、
  次に別の資料を入れたときに前の関係の文が黙って付いてくる
- プロンプトは打鍵のたびに書き、**枠は作り直さない**（フォーカスが飛ぶ）。
  番号も並びも変わらないので、送る文面とキャンバス側だけ追従させる（`afterGroupPromptEdit()`）
- **`referenceDescribeInPrompt`を切ると関係は1文字も送られない。**
  設定した本人には見えない差なので、関係があるときだけ注意書きを出す
- キャンバス側は`signature`に枠も混ぜる。入れないと組み替えたときにしるしが古いまま残る
- **枠の下に、その枠が実際に送る1行をそのまま出す**（`.rs-group-line`）。
  「同じ枠に入れた資料どうしが関係します」だけでは、関係を付けると何がどう変わるのかが読めない。
  下端の「プロンプトに付く説明」は畳んであり、開くまで見えない。
  組み立ては`ReferenceCollector.groupLineFor()`＝`buildPreamble()`と同じ`groupText()`を通す
  （別に組み立てると、片方だけ直したときに食い違う）

### 送信量ではなくトークン

画面に出すのは**トークンの目安**。バイト数は課金にも上限にも直接効かない
（18MBの上限は送信できるかどうかの内部チェックにだけ使い、ツールチップへ回す）。

数え方はGeminiのドキュメントに合わせてある（`estimateImageTokens()`）。

- 幅・高さが両方384px以下 → 258トークン
- それ以外 → `floor(min(幅,高さ) / 1.5)`をタイルの一辺として割り、タイル1枚につき258トークン
  - ドキュメントの例（960x540 → 6タイル / 1,548）と一致することを確認済み
- **ドキュメント自身が「roughly」と書いており、丸め方や上下限は公開されていない。**
  そのため画面には`~`付きの目安として出し、実際の数え方は送信先に従うとツールチップに書く
- コマから取る元画像は送るときに縮小するため、この時点では大きさが分からない。
  分かっている分だけ足し、残りがあることは「+」で示す

### 送る文面

画像ごとの行に関係を混ぜず、**1枠1行で後ろにまとめる**。画像ごとの行に入れると、
3枚組では同じ関係が3回出て何が主語なのか読めなくなる。

```
Image 1: character reference - Aさん
Image 2: object reference - 刀
Image 3: character reference - Bさん
Image 2: shown together with Image 1 - Aさん (右手に刀を持つ)
```

指す先は番号（公式の作例が「the first image」と順番で指す方式のため）。
**番号は組み立てのたびに数え直す**ので、並べ替えても指す先がずれない。

## どこから開くか

| 入口 | 対象 |
|------|------|
| 生成AI設定の並びのボタン（`refSheetButton`） | 今選んでいるもの。ライブラリとして開く経路 |
| コマ／絵の右クリックメニュー「設定資料」 | 押したコマ |
| レイヤーパネルの枚数バッジ（`.layer-ref-count`） | その行のコマ |

**コマ側から開ける経路を必ず残す。** 生成AI設定の並びは「最初に1回いじる設定」の棚で、
設定資料は**コマを作りながら何十回も開く作業ウインドウ**。直したいコマが分かってから
AI設定まで目を戻すことになると、1コマずつ選び直す作業がそのぶん増える。

メニューの項目は**対応していないサービスでも出す**。ここで隠すと、
なぜ資料が効かないのかを読む場所が無くなる（送られるかどうかはウインドウ側が理由付きで出す）。

## 構成

```
js/db/reference-repository.js       ベースの永続化（IndexedDB）
js/ai/reference/
├─ reference-sheet-store.js         プロジェクト（メモリ）とベース（IndexedDB）の2層
├─ reference-collector.js           コマ→送る画像の並び。関係、説明文、プロジェクトファイル連携
├─ reference-sheet-window.js        フローティングウインドウ（管理＋コマへの割り当て）
├─ reference-generator.js          この場で作る（T2Iの割り当てを呼び、共通の資料へ足す）
└─ reference-canvas-overlay.js      キャンバス上の表示（どのコマに何が付いているか）
```

- カテゴリは`character` / `background` / `prop` / `other`の4つ
- 割り当ては**コマ枠（poly）側**に持つ（`referenceIds` / `referenceGroups`、
  `commonProperties`）。枠内の画像を差し替えても設定が残るようにするため。
  **書き込みは`setGroups()`の1か所。** 送る順（`referenceIds`）は枠から作り直す。
  順番と組を別々に持つと、片方だけ直したときに食い違って原因が追えなくなる。
  `referenceGroups`を持たない古い保存は`referenceLinks`から読み替える（`groupsFromLinks()`）
- 一覧はプロジェクトとベースを混ぜて出し、出どころをバッジで示す。
  ベースから複製済みのものは二重に出さない（`copiedFromBaseId`で突き合わせる）

## ウインドウの作り

**暗幕を持たないフローティングウインドウ。** コマ割りを作ってから一気に割り当てる作業では、
モーダルにすると1コマごとに開き直すことになり、そもそもキャンバスのコマを選べない。

- タイトルバー（`#rsTitlebar`）をドラッグで移動、`.rs-resize`（4辺と4隅の8か所）で大きさを変え、
  タイトルバーの`expand_less`で畳む（タイトルバーだけ残す）。
  **右下1か所にしない。** 画面の右端・下端へ寄せると掴み口が画面の外へ出て、そこから広げられない。
  左・上を掴んだときは反対側の辺を動かさない（掴んだ辺だけを動かし、下限に当たった分を戻す）
- 位置・大きさ・畳んだ状態・表示モードは`localStorage`の`referenceSheetWindowPlacement`に残す。
  **開くたびに画面内へクランプする**（`clampPlacement()`）。画面外の位置を覚えていると次に掴めない
- **位置と大きさを戻すボタンは置かない。** クランプが開くたびに走るので、
  戻す手が要る状態にならない。タイトルバーに常時出す価値のあるボタンは畳むと閉じるだけ
- サイドバーのボタンは`toggle()`。開きっぱなしで使うので、同じボタンで閉じられないと畳む以外に消す手が無い
- 生成AI設定のボタンは**隣（`⚙ 生成AI設定` / `🔧 使用モデル・ワークフロー`）と同じく文言の頭に絵文字を置く**。
  マテリアルアイコンを足すと、この3つの中でここだけ別の作りになる。
  絵柄はウインドウのタイトルと同じ`🖼`
- 3つのボタンは`.es-trigger-row`（flex）に入れる。`.input-group`は`1fr auto`の2列グリッドで、
  直に並べると**3つ目だけが次の行の広い列へ落ちて幅いっぱいに伸びる**。
  高さは`align-items:stretch`で揃える（設定資料のボタンだけ枚数バッジの分だけ背が高い）
- z-indexは`--z-floating-window`。`--z-modal`の設定ウインドウは上に出る
- **`floating-window`クラスは付けない。** 付けると`isVisibleFloatingWindow()`が真になり、
  開いている間ずっとキャンバスの矢印キー移動とEscapeが死ぬ。入力欄へのキー入力は
  hotkeysの既定フィルタ（INPUT/TEXTAREA/SELECT）が弾くため、付けなくても衝突しない

### 割り当ての導線

「どうやってコマに付けるのか」が読めないと、一覧を眺めたまま止まる。

1. ウインドウを開いたままキャンバスでコマをクリック → 上部の「対象コマ」が変わる
2. 一覧のカードで**サムネイル**か**「このコマで使う」ボタン**を押す

**対象コマは選択イベントだけでは追えない。** コマ割りを固めてからロック
（`selectable=false`）を掛けると、押してもfabricは選択を付けず、逆に
`selection:cleared`が飛んで対象が外れる。選択だけを見ていると、ロックしたコマは
押すたびに「対象コマ」が空になり、送る順も欠落表示も読めない。
`canvas.on('mouse:down')`で拾い直す（`pickTargetFromClick()`）。

- fabricは選択を確定させたあとに`mouse:down`を流すため、この中で見る
  `getActiveObject()`は最終形。**選択が付いたクリックはここで捨てる**
  （`selection:*`が受けるので、二重に対象を入れると同じクリックで2回描き直す）
- コマの引き方は**ドロップと同じ`hitTestHost()`**に寄せる。押した場所と落とした場所で
  別のコマが対象になると、どちらが正なのか読めなくなる
- 何も無い場所を押したら外す。ロックしたコマを対象にしている間は`selection:cleared`が
  飛ばないため、ここで外さないと対象を空に戻す手が無くなる
- お絵かき中（`isDrawingMode`）は拾わない。ストロークのたびに対象が動く

**または、一覧のサムネイルをコマへ直接ドラッグする。** 対象コマを切り替えてから
カードを押す2手を、落とすだけの1手にする経路。
ドロップ側も選択を一切通さず、落ちた位置からコマを引く（`hitTestHost()`）。

- 当たり判定は`containsPoint()`（外接矩形）の後に**頂点で取り直す**（`isInsidePolygon()`）。
  斜めのコマ・台形では、矩形だけだと枠の外に落としても当たる
- コマの中に画像が入っていてもコマへ付ける。割り当てはコマ枠に持たせているため
- 落とす前に入り先を枠で示す（`referenceCanvasOverlay.setDropHost()`）。
  この枠は**チップの表示（`#rsShowOnCanvas`）とは別に出す**。表示を切っている人にも入り先は要る
- `#canvas-container`のdropは画像ファイルが来る前提で`files[0].type`を読む。
  ラッパー側で`stopPropagation()`して止め、container側でも枚数を見る

`#rsHowto`にこの手順を出す。**対象が無いとき**と**対象にまだ1枚も付いていないとき**だけ出し、
付いたら消す（用が済んだ案内を残すとウインドウ本体が狭くなる）。

- **カード全体を当たり判定にしない。** 名前と説明の入力欄を常時出しているため、
  カード全体を押せるようにすると入力欄を触っただけで付け外しが起きる。
  押せるのはサムネイルと「対象コマに付ける」ボタンだけ
- **押した時点の状態を読み直す**（`currentAttached()`）。組み立て時の値をハンドラに閉じ込めると、
  カードを作り直さない経路で古い状態のまま付け外しが走る

### 画面の段組み

- **上「送る順（1枚目から）」** — 対象コマへ何が何番で入るかだけを出す。
  送る順がそのままプロンプトの`Image N`なので**番号を出し、シートはドラッグで並べ替えられる**。
  元画像は1枚目に固定なので動かせない（`is-fixed`）。
  **見出しに「このコマ」と書かない。** 対象が何を指すかは`対象コマ`のバーが持っており、
  同じものを別の言い方で2回出すと、どちらが対象なのか読み手が探すことになる
- **下の一覧** — ライブラリ。プロジェクトとベースを混ぜ、出どころをバッジで示す

### カードと表示モード

**名前と説明の入力欄は常に出す。** 「編集」を押してから開く作りだと、
取り込んだ直後の「ファイル名のままのタイトル」を直すのに1枚ずつ2回押すことになる。
入力欄の壁になるのは表示モードで避ける（`.rs-viewmodes`、`localStorage`に残す）。

| モード | 出すもの | 用途 |
|--------|---------|------|
| `grid` | 大きいサムネイル＋名前＋説明＋種類＋操作 | 絵柄を見ながら選ぶ |
| `compact` | 小さいサムネイル＋名前 | 枚数が多いときに見渡す |
| `list` | 横一列に全項目 | 取り込んだ直後にまとめて名前を付ける |

- **サムネイルは市松の明るい下地に`object-fit:contain`で置く。**
  暗い下地＋`cover`だと、透過のあるキャラ表が黒くつぶれて中身が読めない
- **対象コマが無いことを理由に一覧を薄くしない。** 以前は`is-disabled`で全カードを
  `opacity:0.45`にしていたため、モーダルでコマを選べない＝常に全部暗い状態だった。
  薄くするのは14枚の上限に達したときだけ（`is-blocked`）
- 拡大表示（`#rsZoom`）をサムネイルの`⤢`から出す。小さい画像では絵柄の細部が読めない
- 名前・説明の編集は**打鍵のたびに反映**する。一覧は作り直さず、名前を出している
  「送る順」の帯とキャンバス側だけを追従させる（作り直すとフォーカスが飛ぶ）。
  ベース側はIndexedDBに書くので400msまとめる

### 作り直しを抑える

ウインドウは開きっぱなしで、**キャンバスを1回押すたびに`render()`まで来る。**
毎回カードを作り直すとシートの枚数分だけ`data:`URLの画像を読み直すことになり、
選択のたびに一覧がちらつく。

- 並んでいる顔ぶれ（表示モード＋カテゴリ＋検索語＋idの並び）を`cardsSignature`に持ち、
  同じなら`updateCardStates()`で**付いているかどうかだけ**当て直す
- 付いているかで変わる見た目は`applyCardState()`の1か所に集める。
  組み立て側（`buildCard()`）には状態を持たせない
- それでも打鍵中に作り直しが起きうるので、フォーカスは
  id＋項目名で取り直す（`captureFocus()` / `restoreFocus()`）。**編集中かどうかをDOMに持たせない**

### 言語の切り替え

このウインドウの文言はほぼ全部JSが組み立てて`textContent`へ入れる。
`updateContent()`は`[data-i18n]`の付いた静的な要素しか見ないため、
**切り替えても案内文・スロット・カードは前の言語のまま残る。**

`i18next.on('languageChanged', ...)`で`cardsSignature`を捨ててから`render()`し直す
（`reference-sheet-window.js`のDOMContentLoaded内）。顔ぶれが変わっていなくても
カードの文言は変わるので、作り直しの判定を先に捨てないと一覧だけ古いまま残る。
文言ごとに`data-i18n`を撒く手は取らない。足すたびに書き漏れる。

### ドラッグ&ドロップ

**ドラッグ中しか出ない表示だけでは、ドロップできること自体に気づけない。**
一覧の先頭に破線の枠（`rs-add-tile`）を常設し、押せばファイル選択、落とせば追加、という
同じ場所に両方を置く。一覧が空でも埋まっていても位置は変えない。

- ウインドウのどこへ落としても現在のカテゴリのベースへ追加する（落とす場所で迷わせない）
- ドラッグ中はオーバーレイに**入れ先のカテゴリ名を出す**（「登場人物」に追加）。
  「ここに置ける」だけでは、どこへ入るのかが分からない
- **カテゴリタブへ落とすとそのカテゴリへ入る**。タブの上に来たらオーバーレイの文言も切り替わる
- 画像以外を落としたら**黙って無視せず**ファイル名を出して知らせる
- 絞り込み中はタイルを出さない。検索結果と追加口が混ざるため
- `dragenter`/`dragleave`は子要素をまたぐたびに飛ぶ。深さを数えないとオーバーレイが点滅する
- スロットの並べ替えも同じHTML5 DnD。ファイルのドラッグと区別するため
  `dataTransfer.types`に`Files`が含まれるかで振り分ける
- **サムネイルの`img`は`draggable=false`にする。** `img`はブラウザ既定でドラッグでき、
  Chromeはそれを**ファイルとして**落とすため、ウインドウのドロップ口が反応して
  **動かしただけで同じ絵が2枚になる**。掴ませたいのは親（`.rs-thumb-wrap` / `.rs-slot`）の側
- ウインドウの中から始まったドラッグは追加として受けない（`isInternalDrag()`）。
  独自のtype（`application/x-reference-sheet`）を載せて見分ける
- 掴めるのは**サムネイルだけ**。カード全体を`draggable`にすると、常時出している
  名前・説明の入力欄で文字を選ぼうとしただけでドラッグが始まる

### スロットのサムネイル

`fabric`が持っている画像要素の`src`をそのまま使う（`layerThumbSrc()`）。
プレビューのために`imageObject2Base64ImageEffectKeep()`で描き直すと、
再描画のたびに原寸2倍の画像を作ることになる。

## キャンバス上の表示

ウインドウは**今選んでいるコマ**しか見せない。ページ全体で何がどこに付いているのかは
一枚ずつ選び直さないと分からず、付け忘れたコマがそのまま生成に流れる。
そこでコマの左上に、割り当てたシートのサムネイルを並べたチップを出す（`reference-canvas-overlay.js`）。

- 置き場所は**fabricのラッパー**（`canvas.wrapperEl`）。キャンバスと同じ論理座標系なので、
  `#canvas-container`のCSS拡大にも`#resizable-container`のスクロールにも勝手に追従する。
  `document.body`へ置くと、スクロールしたときサイドバーの上に取り残される
- 見た目の大きさだけは倍率の逆数（`--rs-chip-inv`）で戻す。
  拡大率0.3のままだとサムネイルが潰れて何が付いているのか読めない。
  倍率は**DOMから実測する**（`getCanvasDisplayScale()`）。このアプリはfabricの
  `viewportTransform`を使わずCSSの`transform:scale()`で拡大している
- 更新は`after:render`＋スクロール＋`resize`。**1フレームに1回へまとめる**。
  中身（idの並び）が変わったときだけ作り直し、位置合わせだけは毎回走らせる。
  毎フレームDOMを作り直すと、拡大やドラッグのたびに`data:`URLの画像を読み直すことになる
- **実体の無い参照は黙って飛ばさず`!N`で出す**。生成が例外で止まる理由をキャンバス側から読めるようにする
- チップを押すとウインドウを開き、そのコマを対象にする（`open(host)`）。
  **選択とは別に対象を持つ**（`setTargetHost()`）。ロックしたコマは選択が付かないため、
  `setActiveObject()`だけに頼ると押しても対象が変わらない。
  開いた直後は`getBaseAll()`の後に`refreshTarget()`が走るので、外から入れた対象は
  `open()`に渡さないと選択中のものへ戻る
- サムネイルは44px。24pxではキャラ表とロケ表の区別が付かず、付いているかどうかしか読めない
- **1枚も省かない。** 「+3」で数だけ出すと、何が付いているのかを見るのに結局コマを選び直すことになり、
  キャンバスに出している意味が無くなる。並びきらない分は**コマの幅で折り返す**
- **枠もウインドウと同じ形で出す**（`.rs-canvas-group`）。1枚だけの枠は囲まない。
  同じ資料を複数の枠で使っていれば、その枚数だけ枠の中に出る（送る画像は1枚のまま）
- **入れ物（チップ）自体には枠も下地も持たせない。** 中の枠と二重になり、
  どちらが関係の印なのか読めなくなる。当たり判定はサムネイルと枠だけにして、
  隙間はキャンバスへ通す（`pointer-events`）。
  **`:hover`も同じ。** 下地を敷くと押した瞬間だけ外側の囲みが増える。
  形に沿って少し光らせる（`brightness`＋`drop-shadow`）だけにする
- 枠には**鎖のしるし（`link`）を先頭に置く**。囲みだけでは「なぜ囲まれているのか」が読めない
- 組に入っていない1枚も**枠と同じ余白・同じ太さの透明な線で包む**（`.rs-canvas-solo`）。
  包まないと枠の分だけ上へずれて、並びが揃わない
- **枠に色味も塗りも極力持たせない。** 絵の上に出るものなので、原稿より目立ってはいけない。
  下地は白のコマにも黒い絵にもなるため、**中間のグレー（#969696）の1px線**にする
  （白にも黒にも明度差が出る）。塗りは輪郭を助ける程度（`rgba(0,0,0,0.12)`）に留める。
  濃い灰色を敷くと絵に膜が掛かって見え、赤や2pxの線は絵より目立つ。
  `--color-accent`（#810000）の細線は逆に絵の上でまず見えない
- 枠と枠、枠と単体の間隔（`gap`）は枠の中の間隔より広く取る。同じ間隔だと切れ目が読めない
- 折り返す幅は`reposition()`が渡す（`(コマの幅 - 8) × 倍率`）。
  **チップの中身は倍率の逆数で戻している**ため、キャンバス上の幅をそのまま渡すと、
  拡大するほど折り返しが早まる。画面上の大きさへ換算してから渡す。
  サムネイルは倍率によらず44pxのままなので、縮小するほど1行に入る枚数が減る
- DOM要素なので、キャンバスの書き出し・保存・履歴には一切入らない
- 表示の切り替えは**ウインドウの帯（`#rsShowOnCanvas`）とメニューの表示タブ
  （`#view_reference_marks_checkbox`）の2か所**。状態は`referenceCanvasOverlay`だけが持ち、
  `localStorage`の`referenceCanvasOverlayEnabled`に残す。
  **チェックの同期は`setEnabled()`から`syncCheckboxes()`の1か所だけで行う。**
  片方のonchangeでもう片方を触る作りにすると、入口を増やすたびに直す場所が増える。
  `SETTINGS_SCHEMA`には入れない（設定側にも状態を持たせると正が2つになる）

## レイヤーパネルの枚数

キャンバスのチップは**切れる**（`#rsShowOnCanvas`）。切っている人には、コマに資料が
付いているかどうかを読む場所が無くなる。レイヤーパネルのコマの行に枚数だけ出す
（`putReferenceCountBadge()` / layer-button.js）。

- 出すのは**枚数だけ**。中身はチップとウインドウが持っている。
  レイヤーパネルの行は名前・進行・ボタンで既に埋まっており、サムネイルを足す幅が無い
- **0件のときは出さない。** 全コマに`0`が並ぶと、付いている行を目で拾えない
- 数えるのは`getAttachedIds()`の**生のid**。実体の有無で数えると、
  シートの読み込みが終わる前に0件に見える（→「実体が見つからないとき」）
- 更新は`setGroups()`から`updateLayerPanel()`を呼ぶ**1か所だけ**。
  付け外し・並べ替え・枠の組み替え・欠落の削除はすべてそこを通るため、入口ごとに書くと足し忘れる
- ツールチップは`addTooltipByElement()`で付ける。**`data-tip`は使えない。**
  `data-tip`の走査は言語切り替えのときに1回走るだけで、
  作り直されるレイヤー行には効かない

## 実体が見つからないとき

`getAttachedIds()`は**生のidをそのまま返す。ここで存在チェックをしてはいけない。**
シートの読み込みが終わる前にフィルタすると、チェックの付け外しで書き戻したときに
他の割り当てまで消える。

存在確認は`resolveAttached()`が`{sheets, missingIds}`に分けて行う。
見つからないものがあるときは:

- ウインドウに「見つからないシートがN件あります」と外すボタンを出す
- **生成は例外で止める**（`collectForLayer()`）。参照が抜けたまま課金して生成させないため

## 送信量とトークン

- インライン画像はリクエスト全体で**20MB**が上限。超えるならFiles API（未対応）
- Gemini側は768x768のタイル単位で258トークン。長辺1024pxより大きくしても
  参照としての情報は増えずトークンだけ増える
- `imageObject2Base64ImageEffectKeep()`は**原寸の2倍**のPNGを返す。コマから取った画像を
  そのまま送ると数枚で20MBに届くため、collector側で必ず`normalizeImage()`を通す
  （長辺1024pxのwebpへ変換）
- 上限（14枚 / 18MB）を超えたら**落とさずに例外を投げる**。黙って間引くと、
  ユーザーが付けたつもりの参照が消えたまま生成される

|--------|----------------|------------|------------|
| Nano Banana 2 Lite (`gemini-3.1-flash-lite-image`) | 14 | **非対応** | **非対応** |
| Nano Banana 2 (`gemini-3.1-flash-image`) | 10 | 4 | 非対応 |
| Nano Banana Pro (`gemini-3-pro-image`) | 6 | 5 | 3 |

## 画像の取り込み

**ウインドウ全体がドロップ先**（`.rs-window`のdrop）。追加タイルを狙って当てる必要は無い。
カテゴリのタブへ落とすとそのカテゴリへ入る（`dropCategoryFor()`）。

- **1枚も無いカテゴリでは追加タイルを一覧の幅いっぱいに広げる**（`.rs-add-tile.is-wide`）。
  カード1枚分の大きさのままだと、開いた直後は隣の空白の方が広く、そちらへ落として素通りする
- **落とす前に枚数を出す**（`refDropIntoCount`）。`dataTransfer.files`はdrop時まで読めないが、
  `dataTransfer.items`の件数はdragover中でも読めるので、`kind==='file'`を数えて出す。
  まとめて掴めることが分からないと1枚ずつ入れることになる
- ウインドウの中から始まったドラッグは追加として受けない（`isInternalDrag()`）。
  ブラウザは画像やカードのドラッグにも`Files`を載せることがあり、
  取り込むと動かしただけで同じ絵が2枚になる

## この場で作る（「AIで作る」）

資料を1枚足すためにアプリを離れてほしくないので、ウインドウの中で生成できるようにしてある
（`reference-generator.js`）。**コマに置かない生成**で、出来た絵は**共通の資料**へ入る
（画像ファイルを足したときと同じ場所）。

- 使うのは**T2Iに割り当てたプロバイダーそのまま**（`getDetachedT2IProvider()`）。
  **ここだけ別のサービスを選ばせない。** 資料とコマで生成サービスが変わると絵柄がずれる
- 対応していないサービスのときは**黙って別のサービスへ回さず**、
  ボタンを押せなくして理由をその場に出す（`refGenUnsupported`）。
  T2Iが「なし」のときも同じ（`refGenNoProvider`）
- 比率は`pickPanelSDXLBucket()`（panel-composition.js）を**そのまま使う**。
  ここで独自に数値を持つと、コマ側のバケットを直したときにここだけ古い値が残る
- タグは生成後も欄に残す。同じ指定で何枚か作って選ぶ使い方をするため
- **説明（note）は自動で埋めない。** 説明はプロンプトに乗るので、
  タグの羅列をそのまま入れると送信文面が汚れる

### キャンバスに置かない生成の経路

コマもレイヤーも無いので、既存の`executeT2I(layer,spinnerId)`は使えない
（配置・生成タスク登録・GUIDがすべてレイヤー前提）。基底クラスに別の入口を足してある。

```javascript
supportsDetachedT2I()                      // 対応していないプロバイダーはfalseのまま
async executeDetachedT2I(request,spinnerId) // request:{prompt,width,height} -> dataURL|null
```

| プロバイダー | 実装 |
|---|---|
| Google / Fal.ai | `CloudImageProvider._executeDetached()`（`_execute()`から配置と生成タスク登録を抜いた形） |
| SD WebUI | `sdwebuiT2IDetached()`。`handleSuccessfulGeneration()`を通らない |
| ComfyUI（local / RunPod） | `comfyuiT2IDetached()`。ワークフローの選択と検証は`comfyuiSelectWorkflow()`に切り出して通常経路と共用 |

- **仮レイヤーは`detachedRequestLayer()`（sdwebui-settings.js）で作る。** `baseRequestData()`は
  レイヤーのプロパティしか見ないので、同じ形を渡せば共通プロンプト・サンプラー・ステップ数が効く。
  `type`はimage以外にする（imageだと寸法を絵の実サイズから取る分岐に入る）
- 進行と取消はレイヤーパネルに出ない（`layerGuid`がnullで、どの行にも紐づかない）。
  ウインドウ内に`data-ai-task-id`付きの行を出し、`refreshAiTaskIndicator()`に
  ステップ数まで書き換えさせる。取消は`cancelAiTask()`
- 失敗・取消の文言は**プロバイダー側だけが出す**。呼び出し側で重ねて出すと、取消でもエラーが並ぶ
- ComfyUIが返すのは**blob URL**。`blobUrlToDataUrl()`で写してから`URL.revokeObjectURL()`する
  （プロジェクトファイルへ入るのはdataURL）

## 未検証のこと

- 関係（`with Aさん in Image 2: 右手に持つ`）で属性の付け先が実際に絞れるか。
