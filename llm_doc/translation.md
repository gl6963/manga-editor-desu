# 翻訳の追加方法

## 基本
- `js/ui/third/i18next.js`の`const resources`に追加
- キー形式: `yyyyMMddHHmmss_SSS`
- 全8言語対応（ja, en, ko, fr, zh, ru, es, de）
- 新エントリは既存の上に配置
- 表示領域を考慮し短文推奨

## 書式
1行1エントリで記述する。

```javascript
// 良い例
"ja":{
"key1":"値1",
"key2":"値2"
}

// 悪い例
"ja":{"key1":"値1","key2":"値2"}
```

## 落とし穴

### 日付キーの重複は翻訳を丸ごと消す
`const resources`のブロックキーが重複すると、JSのオブジェクトリテラルは後勝ちで
**前のブロックが読み込み時に消える**。実際に`"20260803120000_001"`が2回あり、
13キー×8言語＝104件が消えて選択肢がキー名のまま表示されていた。
追加前に必ず重複を確認する。

```bash
grep -oE '^"20[0-9]{12}_[0-9]{3}"[ ]*:[ ]*\{' js/ui/third/i18next.js \
| sed 's/[ :{]*$//' | sort | uniq -d
```

**`:`の前後の空白を必ず含める。** `":\{'`だけで探すと`"20260827000000_001": {`のように
空白を挟んで書かれたブロックに当たらず、**重複していても何も出ない**。

**`:{`まで含めずに探さない。** 翻訳キー自体も`yyyyMMddHHmmss_SSS`形式なので、
`^"20[0-9]{12}_[0-9]{3}"`だけだと`"20260214155000_001":"自動保存"`のような
**普通のキーまで拾って重複に見える**（ブロックキーと同名の翻訳キーは問題ない。
別のオブジェクトなので消えない）。

### 別ブロックに同じ翻訳キーがあるのは異常ではない
`mergeResources()`は`base`を最初に入れ、残りのブロックを**キー名でソートして**
順に`Object.assign`する。つまり**日付が新しいブロックが勝つ**。
古い訳を新しいブロックで上書きするのは意図した使い方で、消えるわけではない。
消えるのは前項の**ブロックキーそのものが重複した場合**だけ。

### どの言語にも無いキーは check-translations で出ない
`npm run check-translations`は言語どうしの突き合わせなので、
**全言語に無いキーは「欠落」として出ない**。`russian`/`spanish`/`Germany`が
未定義のまま、言語切替メニューが生のキー名を表示していた。

実行時は`i18next.init`の`missingKeyHandler`が拾う。
アプリを開いてコンソールの`Translation key not defined`を確認する。

### getText() は未定義でもキー文字列を返す
そのため`getText('x')||'デフォルト'`の右辺は**絶対に評価されない**。
安全網のつもりで書いても効かないので、書かない。

### 属性への翻訳は `[title]key` 記法が使えない
`updateContent()`は`innerHTML`代入のみで属性指定に対応していない。
`data-i18n="[title]copy"`と書くとボタンの中身が`[title]copy`という文字列に置換され、
アイコンごと壊れる。ツールチップは`data-tip`を使う。

### `data-label`（スライダーのラベル）は i18n の書き込み先。値を混ぜない
`updateContent()`は`data-i18n-label`の訳を`data-label`へ書く。
アプリ側が`data-label`へ「ラベル：値」のような文字列を上書きすると、
次の`updateContent()`までは表示が保たれるが、値が動いた瞬間に
**切替前の言語のラベルが焼き付く**（英語に化けて戻らない）。
値は`data-value-text`に分けて持ち、CSSで連結する。
→ 詳細は`ui-patterns.md`の「スライダー」

### スライダーのラベルに末尾の「:」を付けない
表示は`ラベル：値`の形になるため、訳に`:`を含めると`線幅:：2.4`になる。
`lineWidth` / `panelOpacity` がこれで二重になっていた。
